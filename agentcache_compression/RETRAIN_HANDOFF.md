# Handoff: Clean-Data Retrain of the Qwen-7B Centroid (end-to-end)

**For:** an autonomous agent running on a rented GPU.
**Goal:** re-run the *entire* pipeline for the 7B model with **fixed training
data**, then re-measure code quality, to test whether the quality regression we
found is caused by bad training data (fixable) vs intrinsic compression loss
(a floor).

Pipeline: **(1) regenerate training data → (2) quality-gate it → (3) split →
(4) train centroids → (5) export centroids → (6) run multi-turn benchmark →
(7) LLM-as-judge → (8) compare to baseline.**

---

## 0. Why this exists (read first — do not "improve" the plan)

An LLM-as-judge evaluation (gpt-5.5) found that on Qwen-7B, centroid
**compression mode** (system prompt removed, replaced by the centroid) was judged
**worse than the full-prompt baseline in 73% of pairwise comparisons**
(8 win / 0 tie / 22 loss over 30 pairs). Root-cause audit found the training data
is the leading suspect:

- Teacher outputs were generated by **Qwen-1.5B** (a *weaker* model than the 7B
  student), at **temperature 0.9**, possibly under the **search** system prompt,
  with **no quality filtering** → **42% of teacher outputs fail `ast.parse`**.
- The centroid is trained with loss **only on those teacher tokens**, so it
  distilled a 42%-broken distribution into the 7B model.

### The fix is self-distillation — NOT a frontier model, NOT public benchmarks

A prefix does **not** change model weights; it only adds KV context that steers
capabilities **already in the weights**. It cannot install new capability. So the
correct training target is *"what THIS 7B model produces when given the prompt"* —
which is exactly the cold baseline the centroid is trying to match. Targets from a
frontier model or human-written benchmark code are **off-manifold** for the 7B
(it cannot reproduce them), which pulls the prefix into incoherence — the same
failure mode that killed this project's original hidden-state-averaging approach.

**Therefore: teacher = Qwen-7B itself + the coding system prompt + low temperature
+ a quality gate. Do not substitute GPT-4/SWE-bench/etc.** (A frontier-data arm is
an optional *separate* experiment, never the primary.)

### Experimental cleanliness — change ONE variable

Everything except training-data quality must stay **identical** to the original
run: same base model, same N values {64,128,256}, same conversation
(`conversations/csv_cli.json`), same coding system prompt, same judge config.
Otherwise the comparison to the 8W/22L baseline is meaningless.

## 1. Environment

- **Base model:** `Qwen/Qwen2.5-7B-Instruct` (28 layers, 4 KV heads, head_dim 128
  → centroid shape `[28, N, 512]`). Get it: `./get_model.sh Qwen/Qwen2.5-7B-Instruct`
  → `models/Qwen2.5-7B-Instruct/`.
- **GPU:** assume ≥40GB (A100/H100). Do everything in **fp16/bf16, no
  quantization**. Critical rule: **train the prefix and run inference at the SAME
  precision** — a precision mismatch between training and serving adds noise that
  would confound the result. If the GPU is <24GB, stop and flag; quantized
  training/serving is possible but introduces exactly that confound.
- **Setup:** `./install.sh` (also copies the centroid patch into vLLM
  site-packages — required for synthetic mode), `source venv/bin/activate`.
- **For the judge (stage 7):** network access + `OPENAI_API_KEY` set; judge model
  `gpt-5.5` via the Responses API (already implemented).
- **System RAM:** ≥32GB (centroid export loads the base model on CPU in fp16).

## 2. Stage 1 — Regenerate training data (self-distillation)

Use the existing `generate_good_examples.py` (hardcoded PYTHON_TASKS list inside),
but **override its bad defaults**:

```bash
python generate_good_examples.py \

    --system-prompt agentcache_compression/prompts/2000_python_agent_system.txt \
    --temperature 0.1 \
```

Why each override:
- `--model` → the **7B**, not the 1.5B default (self-distillation).
- `--system-prompt` → the **coding** prompt, not the script's **search** default
  (`generate_good_examples.py:11`). This is essential — the teacher must follow
  the coding agent's rules so the centroid can encode them.
- `--temperature 0.1` → near-greedy; the 0.9 default produced broken code.
- `--ensure-goodbye` → restores the GOODBYE behavioral signal (the current
  training file has 0/118 — the signal was lost).

**Output:** check where the script writes (it produced
`good_examples/vllm_good_examples_raw.jsonl` historically). Note the filename — it
must match what stage 3 reads (see gotcha in §4).

**Verify:** open a few outputs; they should be coherent, complete Python. Do not
proceed if they look like the 1.5B garbage (`engine =Alchemy.create_engine(`).

## 3. Stage 2 — Quality gate (NEW — you must write this)

No quality filter exists in the repo; this is the single most important addition.
Write `agentcache_compression/gate_training_data.py` that reads the raw JSONL,
keeps only examples whose largest fenced code block passes `ast.parse`, and writes
a filtered JSONL. Reference implementation:

```python
import json, ast, re, sys

def biggest_block(t):
    blocks = re.findall(r"```(?:python)?\s*(.*?)```", t, re.DOTALL)
    return max(blocks, key=len) if blocks else ""

def ok(rec):
    code = biggest_block(rec.get("teacher_output", ""))
    if not code:
        return False                      # require code for a coding task
    try:
        ast.parse(code)
        return True
    except SyntaxError:
        return False

src, dst = sys.argv[1], sys.argv[2]
rows = [json.loads(l) for l in open(src) if l.strip()]
kept = [r for r in rows if ok(r)]
with open(dst, "w") as f:
    for r in kept:
        f.write(json.dumps(r) + "\n")
print(f"kept {len(kept)}/{len(rows)} ({len(kept)/len(rows):.0%})")
```

```bash
python agentcache_compression/gate_training_data.py \
    good_examples/vllm_good_examples_raw.jsonl \
    good_examples/vllm_good_examples_raw_clean.jsonl
```

**Optional but recommended:** also execute each snippet in a subprocess sandbox
(timeout, restricted) and drop runtime crashers — catches `NameError`/missing
imports that `ast.parse` misses.

**Verify / iterate:** the kept-fraction should be **much higher than the old 58%**
(the 7B at temp 0.1 with the coding prompt should pass ~90%+). If too many examples
are dropped, regenerate stage 1 (more tasks, or lower temp) to keep dataset size up
— aim for **≥100 clean training examples**.

## 4. Stage 3 — Split into train/eval

⚠️ **Gotcha:** `prepare_data.py` hardcodes **search-agent** paths
(`SRC`, `TRAIN_OUT`, `EVAL_OUT` near the top) and may read a different filename
than stage 1 wrote. Either edit those three constants to point at the **clean
coding** raw and **coding** output paths, or do a direct split. Direct split is
safer:

```python
# split into data/python_agent_train.jsonl + python_agent_eval.jsonl
import json, random
rows = [json.loads(l) for l in open("good_examples/vllm_good_examples_raw_clean.jsonl")]
random.Random(0).shuffle(rows)
for i, r in enumerate(rows):
    r["id"] = f"ex_{i}"
    r["teacher_output"] = r["teacher_output"].rstrip()
    if not r["teacher_output"].endswith("GOODBYE"):
        r["teacher_output"] += "\nGOODBYE"      # match original label convention
n_eval = 25
open("agentcache_compression/data/python_agent_train.jsonl", "w").write(
    "\n".join(json.dumps(r) for r in rows[n_eval:]) + "\n")
open("agentcache_compression/data/python_agent_eval.jsonl", "w").write(
    "\n".join(json.dumps(r) for r in rows[:n_eval]) + "\n")
```

**Verify:** `wc -l` both files; train ≥100, eval ~25; every record has
`id`/`user`/`teacher_output`.

## 5. Stage 4 — Train the centroids (one per N)

Same script and hyperparameters as the original run; only the data changed.
Repeat for **N ∈ {64, 128, 256}**:

```bash
for N in 64 128 256; do
  python agentcache_compression/train_prefix_compression.py \
      --model models/Qwen2.5-7B-Instruct \
      --data agentcache_compression/data/python_agent_train.jsonl \
      --system-prompt agentcache_compression/prompts/2000_python_agent_system.txt \
      --output agentcache_compression/adapters/N${N}_qwen7b \
      --num-virtual-tokens ${N} \
      --system-retain-ratio 0.0 \
      --epochs 8 --lr 2e-3 --batch-size 4
done
```

(`--system-retain-ratio 0.0` = compression mode, prompt fully removed during
training — keep it.) **Verify:** each `adapters/N{N}_qwen7b/` has
`adapter_model.safetensors` + `adapter_config.json`; final train loss printed and
not NaN.

## 9. Stage 8 — Compare to baseline and report

**Baseline (bad-data run):** synthetic 8 win / 0 tie / 22 loss (73% loss);
per-N 4/2/2; per-dim worst = completeness (net −22); syntax cold 10/10 vs
synthetic ~8.3/10.

Report the **new** numbers against these and interpret:
- **Loss rate drops sharply / approaches parity (≈50/50):** training data was the
  primary cause → compression mode is viable with clean self-distilled data. Main
  hypothesis confirmed.
- **Loss rate improves but a gap remains:** decomposes the regression — part was
  bad data (now fixed), the residual is the intrinsic compression floor. Still a
  publishable, honest characterization.
- **No improvement:** the bottleneck is the method, not the data — escalate; the
  N-ablation (more N didn't help) already hinted at this.

Write results to a short `results/RETRAIN_RESULTS.md`: the win/tie/loss tables,
the objective syntax-validity comparison, the kept-fraction from the quality gate,
and which interpretation above holds.

## 11. Gotchas

- **Wrong base model in any stage** → centroid shape `[16,…]` or load errors. The
  shape check in §6 is the canary.
- **`prepare_data.py` / `generate_good_examples.py` default to the SEARCH agent**
  — override the system prompt everywhere and reconcile the raw filename.
- **Don't reuse `centroids/`** (Llama). Use `centroids_qwen7b/`.
- **Don't overwrite `results/qwen7b.jsonl`** (the baseline) — write `_clean`.
- **Precision must match between training and serving** (see §1).
- **Synthetic mode needs the vLLM patch** — re-run `./install.sh` on a fresh clone.
- **Do not swap in a frontier/SWE-bench teacher** (see §0) — it breaks the method
  and the experiment.
